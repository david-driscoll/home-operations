# forge-dashboard

[alrayyes/forge-dashboard](https://github.com/alrayyes/forge-dashboard): one page of open pull
requests, issues and CI status across GitHub and the in-cluster Forgejo.
Manifests: `kubernetes/apps/coder/forge-dashboard`. URL: `forge-dashboard.<root domain>`,
internal gateway only.

## First-run setup (manual, once)

The app has **no environment variable for forge tokens**. They are saved from its Settings
page after you sign in, and stored encrypted in `/data` with `ENCRYPTION_KEY`.

1. Open the URL and register a passkey. Registration closes for good after the first one.
2. Settings, Connections, Forgejo: URL `http://forgejo-http.coder.svc.cluster.local:3000`
   (or the public Forgejo URL), token = the renovate bot's PAT, which is
   `forgejo_token` at OpenBao `clusters/equestria/apps/renovate-operator/credentials`.
3. Add a GitHub token there too if you want GitHub repos.

The renovate bot's PAT is scoped for Renovate's needs (repository read/write, issues), which
is wider than a read-only dashboard needs. The dashboard's merge and rerun actions will work
with it.

## Secrets

- `ENCRYPTION_KEY`: generated by `stacks/system/forge-dashboard.ts` into OpenBao
  `clusters/equestria/apps/forge-dashboard/credentials`. Rotating it invalidates the saved
  tokens: enter them again.
- Passkeys are bound to `RP_ID`/`RP_ORIGIN` (the hostname). Renaming the host breaks them.
  Lost every passkey: `forge-dashboard reset-passkeys --yes` against the data volume.

## State

`/data/forge-dashboard.db` on a VolSync-backed PVC (1Gi). The cache inside is refillable.
