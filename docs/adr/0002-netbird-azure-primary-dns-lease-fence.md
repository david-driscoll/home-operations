# NetBird's management server runs on Azure, with a DNS lease as the fence

The plan put the management server on OCI's Always Free tier, with Azure as the fenced standby (D3, D5). OCI never had Arm capacity in the tenancy's only region, and a free-only tenancy cannot use another region. So Azure East US 2 became the primary host and Azure Central US the standby. The OCI VM is parked (`ociVm: false`), and the OCI quota, budget and network stay ready for it to rejoin as a standby. At most one host may run the management server: two at once would split the account. The arbiter is the public DNS record for its name, not a lock service. Each host starts the management server only if that record resolves to its own address, and failover is a watchdog in Equestria moving the record. A consensus store or a shared database were rejected, because DNS is the thing clients follow anyway. A host that disagrees with DNS is useless to clients even if it runs.

## Consequences

- The Azure VMs cost about $64 a month out of a credit-limited subscription with its spending limit on. Exceeding the limit stops every VM, so exit nodes on Azure are held off.
- Failback is manual and runbooked (`docs/runbooks/netbird-failback.md`, D8).
- A host that boots while the lease points elsewhere stays passive by design.
- Decision log: D3–D8 in `docs/plans/netbird-mirror.md`, plus D48 ("Azure primary, OCI parked").
- **2026-11-07 (#3161): a flip needs two views of the holder, Equestria's and another host's.** From Equestria alone, a dead primary and Equestria losing just its route to the primary look the same. Automatic failover for a dead primary has to stay, so the second view comes from outside home. Every host probes management at every other host every 30 s, with the same GET the watchdog makes and the certificate verified for the lease's name. It publishes what it saw to Garage as `failover-view/<host>.json` in the NetBird backup bucket (`components/netbird/failoverView.ts`, deployed by `stacks/netbird-edge`). The watchdog flips only after its 5 failures in a row **and** a view from another host, at most 3 minutes old by Garage's `Last-Modified`, that saw the holder down too. If that view is missing, stale, says healthy, or Garage is unreachable, the watchdog holds and pages `NetbirdFailoverBlocked`.
  - **Why Garage.** Both ends already reach it and hold its key. The hosts back up there over the tailnet (the `netbird-edge-backups` grant), and Equestria reaches the `garage-s3` VIP through its egress; the watchdog reads the key from the same OpenBao record. Writes are SigV4-authenticated, so only a holder of the bucket key can publish. Freshness is Garage's own clock, so a host's clock can't make an old view look new.
  - **Rejected:** Gatus can't serve as the store. Its pushes use a token derived from the endpoint's name, and reading results would need a new route past the app's auth, an Equestria egress Service and an ACL grant. A DNS TXT record would need a Cloudflare token on the hosts that could also move the lease. An HTTPS endpoint behind the standby's Traefik would need a new server, because Traefik serves no files. The relay probes and Gatus's relay checks aren't independent views of management: one checks the home relay, the other runs from home.
  - **Known limits.** The watchdog reads with the bucket's read-write key, the only key the bucket has; a read-only key is a stacks/system follow-up. A standby that is itself on a broken path to the primary would also report it down. Requiring both views is what guards against that: the two paths have to fail together.
  - In the same change: 5 runs in a row that can't read Cloudflare page `NetbirdFailoverWatchdogBlind` and never flip, and only unbroken streaks of failures count.
